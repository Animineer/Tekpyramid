✅ If interviewer asks: “What is React Query?”
 
Your answer:
"React Query is a library used for server-side state management.
It handles API caching, refetching, background updates, loading/error states, and removes the need for useEffect + useState for fetching."
 
✅ If interviewer asks: “Why QueryClient & QueryClientProvider?”
 
Your answer:
"QueryClient is a global cache manager.
QueryClientProvider makes that cache available to the entire app.
All hooks like useQuery and useMutation depend on this provider."
 
✅ If interviewer asks: “What is useQuery?”
 
Your answer:
"useQuery is used for GET requests. It fetches data, caches it, handles loading/error states, and refetches automatically."
 
✅ If interviewer asks: “What is useMutation?”
 
Your answer:
"useMutation is used for POST, PUT, DELETE. It does not run automatically — it runs manually when we call mutate()."
 
✅ If interviewer asks: “What is useQueryClient?”
 
Your answer:
"useQueryClient gives access to the global cache. We use it to read cache, update cache, or invalidate queries."
 
✅ If interviewer asks: “What is setQueryData?”
 
Your answer:
"It updates the cached data manually without calling the API. Used for optimistic updates."
 
✅ If interviewer asks: “What is getQueryData?”
 
Your answer:
"It reads existing cached data. Useful to check if data is available before refetching."
 
✅ If interviewer asks: “What is invalidateQueries?”
 
Your answer:
"It marks a query as stale. React Query will refetch fresh data from the server.
Used after delete/update operations."

🎤 4. Final Golden Answer Format (copy this in interview)
 
Here is a single, perfect summary:
 
“React Query helps me manage server state effectively.
I initialize QueryClient globally and wrap the app with QueryClientProvider.
For fetching, I use useQuery with a queryKey and queryFn.
For POST/PUT/DELETE, I use useMutation.
After a mutation, I use the queryClient to either setQueryData for instant UI updates or invalidateQueries to refetch fresh data.
I also use getQueryData to read existing cached values.
This avoids using useEffect and gives automatic caching, refetching, and better performance.”
